# Форматы входных данных

Все значения и пути в примере синтетические. Профиль относится к одной группе
зашифрованных файлов; универсального ключа или встроенных ключей жертв нет.

## Профиль JSON

| Поле | Значение |
| --- | --- |
| `key_blob_sha256` | SHA-256 последних 128 байт зашифрованного файла, 64 символа hex. |
| `stream_hex` | Известные байты потока шифрования метаданных в hex. |
| `known_mask_hex` | По одному байту `01` для известной позиции потока и `00` для неизвестной. |

Поток и маска имеют одинаковую длину и покрывают область метаданных нужного файла.
Неизвестные байты потока обычно заполнены нулями; значение нуля само по себе
не означает, что байт известен. CLI принимает JSON размером до 2 МиБ.

`stream_hex` — поток для XOR с метаданными. Полное **состояние Salsa20 длиной
64 байта** находится внутри расшифрованных метаданных и применяется к содержимому
файла. Это разные данные. Поток `encrypted XOR original` содержимого отдельной
пары не заменяет профиль метаданных.

## Footer и схема шифрования

Числа хранятся в little-endian. Конец файла имеет вид:

```text
содержимое | зашифрованные метаданные [N байт] | N [uint16] | checksum [uint32] | key_blob [128 байт]
```

Последние 134 байта фиксированы. Поддерживаемый размер `N` — от 83 до 8192 байт.
Группа определяется точным SHA-256 `key_blob`; RSA-расшифровка и проверка его
checksum здесь не выполняются. В синтетическом примере `key_blob` — тестовые
байты, checksum равен нулю.

После XOR метаданные содержат:

| Поле | Размер |
| --- | --- |
| Исходное имя UTF-16LE с завершающим нулём, сжатое aPLib | `N − 82` байта |
| Длина сжатого имени | `uint16` |
| Размер пропуска незашифрованного содержимого | `uint64` |
| `before` | `uint32` |
| `after` | `uint32` |
| Состояние Salsa20/20 для содержимого | 64 байта |

Сначала обрабатываются `before + 1` блоков по 128 КиБ, затем выполняется пропуск.
Дальше повторяются `after + 1` зашифрованных блоков и пропуск. Последний блок
ограничивается оставшейся длиной содержимого. Счётчик Salsa20 продолжается между
зашифрованными участками; пропуски его не увеличивают. Размер пропуска должен быть
не меньше 128 КиБ и кратен 128 КиБ; `before` и `after` — от 0 до 4095.

Обычный режим требует все байты метаданных и совпадение исходного имени.
`--allow-unknown-name` допускает неизвестные байты сжатого имени при полностью
известных последних 82 байтах; проверка известного имени при этом сохраняется.
Без `--expected-sha256` исправность содержимого независимо не подтверждается.

## ZIP с известными парами

В корне архива нужен `manifest.json` со следующей структурой; хеши в примере
обозначены словами и должны быть заменены фактическими 64 символами SHA-256:

```json
{
  "pair_count": 1,
  "pairs": [{
    "inode": 1,
    "category": "synthetic",
    "validation": "synthetic_fixture",
    "encrypted": {
      "archive_path": "encrypted/encrypted.bin",
      "size": 256,
      "sha256": "SHA256_OF_ENCRYPTED_BYTES"
    },
    "decrypted": {
      "archive_path": "decrypted/a.txt",
      "original_name": "a.txt",
      "size": 28,
      "sha256": "SHA256_OF_ORIGINAL_BYTES"
    }
  }]
}
```

`pair_count` обязан совпадать с длиной непустого `pairs`. Для обеих сторон нужны
`archive_path`, точный размер `size` и SHA-256 всего элемента. Для `verify` также
нужно `decrypted.original_name`. Необязательный `inode` служит идентификатором записи;
реальный номер файловой системы не требуется. `category` и `validation`
необязательны. `original_name` у зашифрованной стороны допустим, но не используется.

Пути должны быть уникальными, относительными и не содержать `..`, обратных слешей
или нулевых байтов. Запрещены ссылки, специальные файлы, повторные имена/ключи JSON
и архивы с паролем. ZIP читается без извлечения. Лимиты: 2000 элементов, 64 МиБ
на элемент, 128 МиБ суммарно, 2 МиБ для manifest.

`analyze` проверяет архив и извлекает частичное покрытие потока из поля длины
сжатого имени; он не получает автоматически полный профиль. `verify` сравнивает
расшифрованное содержимое с предоставленными оригиналами. Совпадение подтверждает
эти пары, но не доказывает достоверность исходного архива.

Для рабочего примера выполните `python examples/make_demo.py demo-output` после
установки пакета. Он создаёт только новую папку и не перезаписывает существующую.
